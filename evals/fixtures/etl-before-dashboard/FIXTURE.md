# Orders export fixture

A 240-row order export in the shape a spreadsheet on Windows produces. Every value is
**synthetic**: no real people, companies, products or transactions appear here.

## Provenance

Generated by `generate.py` in this folder, standard library only, with the fixed seed
`20260904`. Running `python generate.py` rewrites the identical file. The generator was run
once and `orders.csv` is committed so the eval does not depend on it.

## Traps

Each one is deliberate, and each is a Step 1 item in the `etl-before-dashboard` skill.

| Trap | Where | What a careless read does |
| --- | --- | --- |
| Byte-order mark | First three bytes | The first column is not addressable as `order_id` |
| CRLF line endings | Every line | Trailing carriage returns appear inside the last field |
| Ambiguous dates | `order_date`, all rows | Day-first, but only 15 rows have a day above 12 to prove it; the other 225 parse either way |
| Decimal comma | `amount`, two rows in three | `1.361,11` read as a dot-decimal becomes 1.361 or fails |
| Mixed number formats | `amount` | One row in three uses a plain dot, so a single format rule cannot cover the column |
| Leading zeros | `store_code` | `007` and `0075` become 7 and 75, merging two stores |
| Several null spellings | `status` | Empty, `N/A`, `-`, `null` and `NULL` all mean missing and none is detected by default |
| Grand total row | Last row | Counted as an order, doubling revenue and adding a null-keyed row |

The correct reading is: day-first dates, `store_code` and `order_id` as text, comma decimals
with a dot thousands separator on two rows in three, five null spellings normalised, and the
final row removed before any aggregate.
