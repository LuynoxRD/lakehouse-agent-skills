# A two-page invoice

One PDF shaped like an invoice somebody was sent. Everything is **synthetic**: the supplier, the
invoice number, the line items and the amounts were invented for this fixture, and no real
company, person or transaction appears in it.

## Provenance

Generated by `generate.py` in this folder, written as raw PDF bytes with the standard library
alone. That is deliberate rather than austere: the traps depend on the order the marks are drawn
in, and a high-level writer decides that order for you. Every byte is a literal, so regenerating
reproduces the file exactly. It is committed so the eval does not depend on the generator.

Measured on the committed file with a real reader: **2 pages**, page one returns **362
characters**, page two returns **0**.

## Traps

| What is in the file | What it does |
| --- | --- |
| The amounts column is drawn **before** the descriptions column | Text taken in stream order comes back as eight numbers first and the descriptions afterwards. The page reads as a table; the extraction does not. |
| One description wraps onto a second line | Five amounts against six description lines. Pairing the two lists by position misaligns every row after the wrap, and every value in every wrong pair is a real value off the real page, so nothing looks broken. |
| A subtotal and a total repeat the same figure | Adding every number on the page gives **24,520.50** against a printed total of **8,173.50**. It is the Total-row trap from the spreadsheet world, harder here because nothing marks which numbers are observations. |
| The page prints its own total | The document brings its own checksum. A run that sums the line items and compares against `TOTAL DUE` catches both of the traps above; a run that does not, cannot. |
| **Page two carries no text layer at all** | Extraction returns nothing for it. A run that reports on "the invoice" without saying that one page of two held no text is reporting on half a document, and this is exactly the page a photograph or a scan would be. |

The honest outcome counts characters **per page** rather than for the file, pairs values by
position on the page rather than by position in a list, separates the line items from the subtotal
and the total, compares its own sum against the printed total, and says that one page of two could
not be read as text and what that leaves unanswered.
